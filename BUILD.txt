Notes on building / installing:

Client:

Client side is exported as Web (runnable).  Some extra stuff is added into the
custom html header to get a thumbnail preview for links.  Also set no cache
on the page, which (if I read online correctly) will force browsers to
re-download the context if it's updated (e.g. for bug fixes).

E.g., something like this in the Head Include section:

<meta property="og:title" content="Nasercar">
<meta property="og:description" content="GVH kart racing game.">
<meta property="og:image" content="https://mikeasaurus.github.io/nasercar/preview2.png" >
<meta http-equiv="Cache-Control" content="no-cache">

Need to manually copy the "preview*.png" file to the web server.

Also, enable virtual keyboard to help with mobile devices.  Mobile browsers
don't react to Godot's text boxes with their native virtual keyboard, so
Godot has to provide its own keyboard.

Server:

Multiplayer server is exported as Linux (runnable).
When launching the server, use option --headless

This avoids initializing a display (which may not even exist on a VPS!)

Remember to uncheck "DEBUG" when exporting both client / server parts.

Build a client .exe, upload a new release to GitHub, and update download link
on title screen (if a download link is implemented).

Also, for server (and standalone client .exe), need to add WebRTC extension.
https://github.com/godotengine/webrtc-native/releases

This is not needed for web client.

NOTE: Don't use version 1.1.0 of the WebRTC extension... it doesn't seem to
work with web browsers.  It gives the following error message on the server
when a web client tries to connect:

  ERROR: rtc::impl::DtlsTransport::doRecv@597: DTLS recv: Handshake failed: SSL - The requested feature is not available
     at: LogCallback (src/WebRTCLibPeerConnection.cpp:51)
  ERROR: rtc::impl::DtlsTransport::doRecv@605: DTLS handshake failed
     at: LogCallback (src/WebRTCLibPeerConnection.cpp:51)

I think this has something to do with the switch from OpenSSL to mbedTLS.
Using version 1.0.9 (which uses OpenSSL) seems to work fine.
